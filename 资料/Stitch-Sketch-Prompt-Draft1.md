# Stitch Sketch Prompt（用于生成 Sketch Draft 1）

生成日期：2026-09-28。以下为交给 Stitch 的完整原文。

---

请为一个个人网站设计 Sketch Draft 1（桌面端，参考视口 1440×900）。

【网站是什么】
这是一个以照片和截图为主的个人记录角落，主要给自己翻看，偶尔分享给朋友。内容分三类：生活照片、截图/摘抄（喜欢的一句话、一张图、一段对话的截图）、不带图的短句/心情碎片。没有长篇文章，也没有单独的文字页。网站只用来浏览，不需要登录、评论、点赞、分享或任何社交功能。内容由站长在本地项目中维护后部署上线，所以页面里不要画任何新增、上传、编辑、保存、发布或后台管理按钮。

【Sketch 的含义】
这一版 Sketch 是“应用骨架＋页面系统”：画清楚网站有哪些页面，页面之间如何进入、切换和返回，每页由哪些主要区域组成，哪些结构在多个页面共用，详情弹窗在哪里出现、如何关闭，以及这些区域在桌面上如何排列。重点是结构和功能入口，不是视觉风格。

【页面与区域】
网站共两个独立页面：首页、收集页。另有一个共用的详情弹窗。

1. 共用结构（两页一致）
- 顶部导航：左侧是网站名（占位“（我的名字）的角落”），点击回首页；右侧是“首页”“收集”两个入口，当前所在页面要有明显的选中状态。
- 页面内容区：两页使用同一个居中内容容器，有合理的最大宽度，两侧留白。
- 页脚：一行简单文字（占位“© 2026 （我的名字）”），没有其他链接。

2. 首页（像一张简单的门面，负责招呼来访者）
- 自我介绍区：一个头像占位、名字占位“（我的名字）”，以及一两句介绍占位“（一句话介绍自己，例如：在这里存放我拍下的、截下的和随手记下的东西。）”。不要编造具体身份或经历。
- “最近”区：显示最近放进来的 6–8 条记录，三类内容混在一起，按时间从新到旧排列。照片和截图显示缩略图和日期；短句直接显示一两行文字和日期，不配图。点击任意一条，直接在首页打开详情弹窗，不跳转页面。
- 区块标题旁或区块底部放一个明显的“查看全部 →”入口，点击进入收集页。

3. 收集页（负责慢慢翻）
- 页头：标题“收集”，旁边或下方显示条目总数的占位，例如“共 128 条”。
- 筛选：一组切换按钮“全部 / 照片 / 截图 / 短句”，默认选中“全部”。切换只改变下方显示的内容，属于同一页面内的状态变化，不是新页面。请画出选中状态，并至少用一张图示意切换到“截图”后的样子。
- 内容区：从新到旧排列，按月份分组，每组上方有月份小标题（例如“2026 年 9 月”）。照片和截图保留各自的原始比例，截图常常是竖长图，不要强行裁成一样的方块；短句是没有图片的纯文字小块，只有文字和日期。三类内容混排时要自然，布局形式可以由你决定，不必全部做成统一的卡片。
- 某个筛选下没有内容时，显示一句简单的空状态提示，例如“这里还没有东西”。
- 内容多时页面自然向下延伸，不要为了塞进一屏而缩小内容。

4. 详情弹窗（首页和收集页共用）
- 点击任意一条记录后，在当前页面上方弹出覆盖层，背后页面变暗，但仍保留原来的滚动位置。
- 照片和截图的详情：大图完整显示，不裁切，长截图可以在弹窗内上下滚动；旁边或下方显示类型标签（照片 / 截图）、日期，以及一段说明文字的占位。
- 短句的详情：用较大的字号完整显示这段文字，并显示日期。
- 弹窗有明显的关闭按钮（右上角 ×），点击背景空白处或按 Esc 键也能关闭，关闭后回到原来的位置继续浏览。
- 弹窗左右两侧有“上一条 / 下一条”箭头，可以在当前浏览范围内切换：在收集页时遵循当前筛选，在首页时只在“最近”这几条里切换。
- 请至少画两张弹窗示意：一张照片或截图的详情，一张短句的详情。

【需要交付的图稿】
- 首页（桌面）
- 收集页：选中“全部”的状态
- 收集页：选中“截图”的状态
- 详情弹窗：照片或截图
- 详情弹窗：短句
直接给出图稿，不需要额外画页面关系图，也不要先写长篇分析。将这一版标为“Sketch Draft 1”。

【视觉要求（这一阶段刻意从简）】
- 只使用中性配色（白、灰、黑，可加一个很淡的强调色表示选中状态），文字清晰，只用简单的边框或分隔线表示区域边界，图片用灰色占位块表示，并标出大致比例（例如 4:3 照片、9:19 竖长截图）。
- 不做复杂装饰，不制作精细素材，不尝试多种视觉风格。视觉风格留到下一阶段再定。
- 只设计桌面端，参考视口为 1440×900。长内容可以自然向下延伸，不靠缩小文字、裁切或隐藏区域来塞进一屏。参考尺寸不代表网页的固定尺寸。

【代码与实现约定（生成或导出代码时遵循）】
- 后续将由开发者使用 React + TypeScript + Vite + Tailwind CSS 实现。导出代码时优先使用 Tailwind 工具类，必要时只补充少量、作用范围明确的 CSS；不要混用其他样式框架。
- 根据实际需要使用 Grid 或 Flex 布局。不要依靠大量绝对定位、固定坐标、偏移、重复覆盖或 !important 拼出整页。
- 颜色、字体、间距、圆角和阴影要集中定义并复用。同类组件（导航项、筛选按钮、内容条目、弹窗按钮）的样式保持一致，并包含必要的悬停、聚焦、选中状态。
- 页面设置合理的宽度和最大宽度，内容可以自然增高。图片比例和裁切规则要清楚：列表中的缩略图如何显示，详情中完整显示。
- 静态样式尽量使用类名或变量，只有在动态数值等必要场景中使用行内样式。

【说明】
- 图中的筛选、弹窗、切换等入口和状态只是设计示意，不代表功能已经实现，也不需要真实的数据保存。
- 次要信息缺失时，请合理安排并在图旁简短注明；只有缺失的信息会明显改变整体结构时再提问。
- 展示 Sketch Draft 1 后请等待我的反馈，保留我认可的部分，不要自动进入视觉精修或代码实现。
